# Contributing to Digger

Thanks for helping. This guide covers running Digger locally and sending a change.

## Where changes go

Digger is published in the [Raycast Store](https://www.raycast.com/chrismessina/digger).
Open pull requests against [`raycast/extensions`](https://github.com/raycast/extensions/tree/main/extensions/digger),
not this repository: Raycast reviews every change there, and merged changes come back here in a
sync pull request. Open [issues](https://github.com/chrismessina/raycast-digger/issues) here or in
`raycast/extensions`, whichever you prefer. Raycast's
[contribution guide](https://developers.raycast.com/basics/contribute-to-an-extension) covers the
fork-and-PR steps.

## Run it locally

You need [Raycast](https://www.raycast.com/) and Node.js 22.22.2 or later.

1. In Raycast, find Digger in the Store and choose **Fork Extension** from the action panel.
   Raycast checks out only this extension's folder from `raycast/extensions`.
2. In that folder, run `npm ci`, then `npm run dev`. Raycast opens the development version, and
   saving a file reloads it.

`npm test` runs `node --test` with `--experimental-strip-types`, so it needs Node.js 22.6 or later.

## Scripts

| Script | What it does |
| --- | --- |
| `npm run dev` | Run the extension in Raycast and reload on save |
| `npm run build` | Build the distribution bundle |
| `npm run lint` | Run Raycast's ESLint and Prettier checks |
| `npm run fix-lint` | Fix what the linter can fix |
| `npm test` | Run the unit tests in `tests/` |
| `npm run cache-schema` | Regenerate `src/utils/cacheSchema.ts` |
| `predev`, `prebuild` | Regenerate the cache-schema hash (`scripts/cache-schema.mjs`) before `dev` and `build` |
| `prelint` | Fail `lint` when the cache-schema hash is out of date (`cache-schema.mjs --check`) |
| `npm run publish` | Open or update the pull request in `raycast/extensions` (`ray publish`) |
| `prepublishOnly` | Stops `npm publish`: the extension goes to the Raycast Store, never to the npm registry |


## How it works

- `src/digger.tsx` is the main command; `src/open-current-tab.tsx` and `src/open-clipboard.tsx`
  start a dig from the browser tab or the clipboard. `src/utils/urlSources.ts` finds the URL.
- `src/hooks/useFetchSite.ts` runs a dig: it fetches the page, parses it with Cheerio, and runs
  the DNS, TLS, Wayback Machine and other lookups. Each section of the result is a component in
  `src/components/`, and its actions are in `src/actions/`.
- `src/utils/networkGuard.ts` guards requests whose URL came from page content rather than from
  you: a sub-resource on the same host is allowed, anything else must resolve to a public address.
- Results are cached (`src/hooks/useCache.ts`). The cache key's version is a hash of the cached
  types, generated by `scripts/cache-schema.mjs` into `src/utils/cacheSchema.ts`. A change that
  alters what a field means without changing its type needs a hand bump of `CACHE_SALT` in
  `src/utils/config.ts`; the header of `scripts/cache-schema.mjs` explains why.
- [`CONCEPTS.md`](CONCEPTS.md) defines the project's vocabulary (a dig, supersession), and
  `docs/solutions/` records past bugs and their fixes.

## Before you open a pull request

- `npm run build`, `npx tsc --noEmit`, `npm run lint` and `npm test` all pass.
- You tried the change in Raycast, including its error and empty states.
- `CHANGELOG.md` has a new entry at the top, dated `{PR_MERGE_DATE}`. Raycast fills in the date
  when the pull request merges.
- New or changed screenshots go in `metadata/`, taken with Raycast's Window Capture.
